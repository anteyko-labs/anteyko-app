# Anteyko: white-label мобильное приложение + витрина + админка

Сводка для анализа проекта. Рядом: [`chat-transcript.md`](chat-transcript.md) (вся переписка по порядку) и [`screenshots/`](screenshots/) (ключевые экраны). Исходники — весь этот репозиторий.

Дата состояния: 12.10.2026. Flutter 3.47, Dart 3.13.

---

## 1. Что заказывали (по порядку)

1. White-label шаблон приложения: по умолчанию каталог, должен подходить как можно большему числу бизнесов.
2. Запустить; затем на другом адресе; затем исправить белый экран на телефоне.
3. Админка: выбран вариант **Supabase + веб-админка**.
4. Расширение: приложение-**витрина студии**. На входе каталог типов приложений (магазин, кафе и т.д.), чтобы клиенты видели, что студия разрабатывает.
5. Красивее, больше анимаций, **разные интерфейсы** для каждого типа.
6. Открывать с телефона «как приложение» (PWA); реагировать на настройки iPhone (прозрачность и т.п.); ещё больше анимаций.
7. «Мега» версия: админка + **3 тарифа** (простой/ограниченный, средний, максимальный); админ включает и выключает отдельные функции и одной кнопкой ставит тариф.

## 2. Что получилось: три режима в одном проекте

| Режим | Как включается | Что это |
| --- | --- | --- |
| Витрина студии | `showcaseMode = true` в `lib/brand/brand_config.dart` (сейчас так) | 6 живых демо, раздел «Тарифы», переключатель тарифа и админка внутри каждого демо |
| Приложение клиента | `showcaseMode = false` | один бренд (`defaultBrand`) |
| Админка | адрес `/#/admin` (веб) или кнопка «Админка» в демо | без Supabase — демо-режим в браузере; с Supabase — вход по email |

Шесть демо, у каждого свой интерфейс (`UiStyle`), шрифт, цвета и каталог:

| Демо | Стиль | Отличия |
| --- | --- | --- |
| Moda (магазин) | `shop` | баннеры с автопрокруткой, сетка карточек |
| Brick Pizza (кафе) | `menu` | тёмная тема, липкие вкладки категорий, блюда списком, плавающая корзина |
| Flora (цветы) | `boutique` | шрифт с засечками, крупный hero, высокие карточки |
| Fresh (продукты) | `grocery` | «− 2 +» на карточке, полки товаров, прогресс до бесплатной доставки |
| Nord Home (мебель) | `showroom` | минимализм, без корзины, заявка на замер |
| Lumière (салон) | `services` | прайс с длительностью, онлайн-запись (мастер, дата, время) |

## 3. Тарифы

Источник правды: `lib/core/features.dart` (`featureInfo`, `planInfo`, `brandBlocks`, `featureRequires`, `isEnabledIn`).

| Функция | Старт | Бизнес | Премиум |
| --- | :-: | :-: | :-: |
| Поиск | ✓ | ✓ | ✓ |
| Корзина и оформление (без неё — заявка) | — | ✓ | ✓ |
| Время доставки, фильтры, избранное, история заказов | — | ✓ | ✓ |
| Онлайн-запись (только `services`), баннеры | — | ✓ | ✓ |
| Промокоды, бонусы, отзывы и рейтинг, сторис | — | — | ✓ |
| Тёмная тема по выбору, English, анимации и «стекло», аналитика в админке | — | — | ✓ |
| Лимит товаров / баннеров | 30 / 1 | 500 / 5 | ∞ |

Как определяется, включена ли функция: `ручное_переключение ?? входит_в_тариф`, затем ограничения типа бизнеса (`brandBlocks`), затем зависимости (`featureRequires`: бонусы, промокоды, время доставки и история работают только с корзиной).

Цены в витрине (`planPrices` в `lib/showcase/demos.dart`) — **заглушки: $490 / $990 / $1 790**, их нужно заменить.

## 4. Архитектура

```
lib/
  main.dart                 выбор режима: админка / витрина / приложение клиента
  brand/                    brand_config.dart (бренд, UiStyle, флаги бренда), strings.dart (RU/EN на лету)
  core/
    features.dart           тарифы, функции, AppSettings (тариф + ручные переключения + промокоды + бонусы)
    app_state.dart          ChangeNotifier: каталог, настройки, корзина, избранное, заказы, бонусы, отзывы, тема/язык
    backend.dart            интерфейс ShopBackend + AssetBackend (каталог из файла)
    local_store.dart        LocalStore: база в браузере (SharedPreferences), её же правит админка; генерация демо-данных
    supabase_backend.dart   SupabaseBackend
    rows.dart               строки таблиц ↔ модели
    models.dart             Catalog, Product, Order (скидка, промокод, бонусы, время доставки), Review…
  ui/
    store_app.dart          корень приложения: пересборка при смене тарифа/темы/языка
    screens/                shell (вкладки, плавающая корзина), home_layouts (6 главных), checkout, product, booking_sheet…
    widgets/                product_card (6 видов карточек), stories, reviews, fly_to_cart, confetti, cart_actions
    glass.dart, motion.dart «стекло» и анимации; учитывают системные настройки и тариф
    system_prefs.dart       «Понижение прозрачности» / контраст: веб (CSS media queries) + iOS (MethodChannel)
  admin/
    admin_app.dart          оболочка: разделы зависят от включённых функций; телефон — нижнее меню + «Ещё»
    dashboard_page.dart     аналитика (KPI, график выручки, топ товаров, статусы)
    settings_page.dart      «Тариф и функции»
    products/categories/orders/marketing_pages.dart
    admin_api.dart          интерфейс AdminApi + Supabase-реализация
    local_admin_api.dart    AdminApi поверх LocalStore (демо без сервера)
  showcase/                 витрина: demos.dart (демо, цены тарифов), showcase_app.dart
supabase/schema.sql         таблицы, RLS, place_order (пересчёт цен, проверка промокода, лимит бонусов), лимит товаров триггером
ios/Runner/AppDelegate.swift  мост «Понижение прозрачности»/«Увеличение контраста» → Flutter
web/                        PWA: manifest, иконки, заставка загрузки
tool/rebrand.dart           смена названия и bundle id
tool/generate_icons_test.dart  генерация иконок PWA
```

Объём: около 13,6 тыс. строк в `lib/`, около 680 строк тестов, около 330 строк SQL.

### Потоки данных
- **Без сервера.** `LocalStore` (на каждый бренд свой ключ в localStorage) — это одновременно `ShopBackend` для приложения и источник для `LocalAdminApi`. Правка в админке → `notifyListeners` → `AppState.reload` → приложение перестраивается.
- **С Supabase.** `SupabaseBackend` / `SupabaseAdminApi`. Заказ создаётся только через RPC `place_order` (security definer).
- **Глобальное состояние.** `brand`, `appSettings` и `S.lang` — глобальные переменные: одновременно активно одно приложение. В витрине настройки задаёт только активное `AppState` (`AppState._active`).

## 5. Как запустить

```bash
cd app
flutter pub get
flutter test                       # 16 тестов
flutter run -d chrome              # или устройство
flutter build web --release --no-web-resources-cdn
python3 -m http.server 8095 --bind 0.0.0.0 --directory build/web   # доступ с телефона в той же сети
```

Supabase: создать проект → выполнить `supabase/schema.sql` (+ `seed.sql`) → завести пользователя и добавить email в `admins` → вписать `supabaseUrl` / `supabaseKey` в `brand_config.dart`. Подробно — в `app/README.md`.

## 6. Что проверено

- `flutter analyze` без замечаний; **16 тестов проходят**. Они покрывают: тарифы и ручные переключения, ограничения типа бизнеса, зависимости функций, сериализацию настроек, промокод + бонусы в заказе, связь «админка ↔ приложение» через общую базу, смену тарифа и ручное включение в UI админки, лимит товаров, вход в админку, смену статуса заказа, создание товара, витрину (открыть демо и вернуться), парсинг всех 6 каталогов.
- SQL-схема применена к локальному Postgres (с заглушками `auth`/`storage`), повторный запуск тоже проходит. Проверено:
  - аноним видит только активные товары и не видит заказы;
  - цена из клиента подменяется ценой из базы;
  - поддельный промокод игнорируется, WELCOME10 даёт ровно 10%;
  - бонусы режутся до 30% заказа;
  - аноним не может опубликовать отзыв или сменить тариф;
  - 31-й товар на тарифе «Старт» отклоняется.
- Экраны просмотрены рендером в тестах с настоящими шрифтами (см. `screenshots/`); живая веб-сборка открыта в Chrome.
- Тестами найдены и исправлены реальные баги, в том числе:
  - падение выпадающего меню тарифа вне MaterialApp;
  - неизменяемая карта статусов;
  - перезапись тарифа неактивным демо;
  - дублирующиеся Hero-теги;
  - `setState` с Future в админке.

## 7. Что не проверено и известные ограничения

- **Нативные iOS/Android не собирались**: на машине нет Xcode и Android SDK. Swift-мост в `AppDelegate.swift` не компилировался.
- **Supabase вживую не подключался**: проекта нет. Клиентский код к Supabase не прогонялся против реального сервера; SQL проверен на локальном Postgres.
- **С реального телефона я не проверял.** «Понижение прозрачности» в Safari может не передаваться сайтам (`prefers-reduced-transparency`); «Уменьшение движения» и тёмная тема работают через стандартные механизмы.
- **Демо-режим хранит данные в браузере** конкретного устройства: у разных устройств разные данные. Картинки в демо-админке ограничены 400 КБ (хранятся как data URL).
- **Бонусы считаются на устройстве покупателя.** На сервере списание ограничено долей заказа, но баланс не синхронизируется между устройствами.
- **Фото товаров** нет: везде цветные заглушки с иконками категорий.
- **Цены тарифов** — заглушки.
- **Глобальные `brand` / `appSettings`** — осознанное упрощение под «одно приложение за раз»; при развитии стоит перейти на DI/InheritedWidget.
- **Вес веб-сборки:** первая загрузка около 13 МБ без сжатия (движок ~7 МБ, код 3,3 МБ, шрифты 3 МБ).

## 8. Что стоит проанализировать в новом чате

1. Модель тарифов: правильно ли распределены функции между «Старт / Бизнес / Премиум» для продаж; цены.
2. Готовность к продакшену: публикация в App Store / Google Play, хостинг (HTTPS), подключение Supabase.
3. Безопасность: RLS и `place_order` в `supabase/schema.sql`, хранение бонусов.
4. Архитектура: глобальное состояние, размер `showcase_app.dart` и `home_layouts.dart` (более 1000 строк каждый), покрытие тестами.
5. UX: скриншоты всех демо и админки, тексты витрины.
